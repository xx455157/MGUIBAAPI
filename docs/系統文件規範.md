# 系統文件標準格式 (System Documentation Format Standard)

## 文件規範目的

本文件規範旨在統一所有系統文件的格式與內容，確保文件的一致性、可讀性及可維護性。透過標準化的文件結構，提高系統文件的品質，便於開發團隊間的溝通與技術交流。

## 系統文件標準格式

所有系統文件(MD檔案)必須遵循以下標準格式:

```markdown
# [系統代碼] [系統名稱] 系統資料表總覽

## 系統介紹

[系統代碼][系統名稱]系統是一個[系統主要功能]系統，主要負責處理[主要業務領域]相關業務，包括[功能1]、[功能2]、[功能3]等功能。系統包含多個資料表來記錄[主要資料類型]及相關業務資訊。

## 系統文件建立規則

### 1. 檔案位置與命名規則

- **系統總覽文件位置**：所有系統總覽文件應存放於 `File Description/[系統名稱]/` 目錄下
- **檔案命名規則**：系統文件使用系統代碼作為檔名，如 `ARTHPY.md`
- **附屬文件目錄**：系統相關的程式說明文件應位於 `File Description/[系統名稱]/Programs/` 目錄下

### 2. 內容組織規則

系統文件須包含以下內容：

1. **系統介紹**：
   - 簡要說明系統的主要功能和業務領域
   - 提供系統的整體概述和使用背景
   - 說明系統的主要用戶群體和業務價值

2. **資料表列表**：
   - 完整列出系統包含的所有資料表
   - 提供到各表格詳細文件的連結
   - 簡要描述每個表格的主要功能

3. **資料表關聯圖**：
   - 使用mermaid語法描述表格間的關聯關係
   - 依照功能模組對表格進行分組
   - 清晰表示表格間的依賴和關聯關係

4. **系統架構**：
   - 詳細說明系統的模組結構
   - 描述模組間的關聯和交互方式
   - 提供主要業務流程的步驟說明

5. **版本歷史**：
   - 記錄文件的更新歷史
   - 說明每次更新的主要內容

### 3. 文件更新與維護規則

1. **版本控制規則**：
   - 每次文件更新必須在版本歷史記錄中添加新的版本記錄
   - 版本號遵循 `主版本.次版本` 格式，如 `1.0`, `1.1`, `2.0`
   - 重大架構變更增加主版本號，小幅內容更新增加次版本號

2. **結構更新規則**：
   - 新增或刪除資料表時，必須同時更新資料表列表和關聯圖
   - 修改系統架構時，必須同時更新模組結構和關聯說明
   - 更新業務流程時，必須同時更新相關的流程描述

3. **關聯維護規則**：
   - 確保系統文件中的資料表列表與實際目錄結構保持一致
   - 資料表關聯圖必須反映最新的表格間關係
   - 當表格關聯發生變化時，必須更新相關模組的關聯說明

4. **文件缺失處理規則**：
   - 當系統中的資料表找不到對應的MD文件時，不做完善處理
   - 僅在相對應的MD文件正式建立後，才進行相關處理和關聯設定
   - 在文件列表中可標記尚未建立文件的資料表，但不建立空的連結或關聯

### 4. 文件品質要求

1. **內容要求**：
   - 系統介紹應簡明扼要，重點說明系統的業務價值和主要功能
   - 資料表列表必須包含所有相關資料表，並提供到各表格文件的連結
   - 模組結構說明應包含每個模組的核心表格、主要功能和業務流程

2. **格式要求**：
   - 使用標準Markdown語法，保持格式一致性
   - 資料表關聯圖應使用mermaid語法，並根據功能模組進行分組
   - 表格和列表應使用標準的Markdown表格和列表格式

3. **審核要求**：
   - 新建或修改的系統文件應經過技術審核
   - 確保文件中的業務流程描述準確反映實際流程
   - 確保關聯描述與實際系統設計保持一致
